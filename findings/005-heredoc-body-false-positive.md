# 005 · 쓰기 범위 훅이 heredoc 본문의 `->`·`<tag>`를 리다이렉션으로 오인한다

- **발견**: night-003 (GreedyAtena, 2026-08-29 00:09, opus). SUMMARY 이상 징후 "훅 거부 1회: task-004". 스트림: 3번째 도구 호출 `cat > tests/test_collectors_news.py <<'EOF' …(132줄)… EOF`를 pre-tool이 `[harness] Bash 쓰기 대상 str:: 쓰기 범위 밖: str: (허용: tests) (I6)`로 거부. 실제 쓰기 대상 `tests/…`는 범위 안이었다.
- **증상**: `harnesslib.bash_write_targets`가 이 명령에서 쓰기 대상 **10개**를 뽑았고 진짜는 1개 — 나머지는 heredoc 본문의 `def f() -> str:`(파이썬 반환 주석) · `<title>{title}</title>`(XML f-string) · `# … -> de-duped,`(주석). `_REDIRECT_RE`의 lookbehind가 `<>&`만 제외하고 `-`를 제외하지 않으며, heredoc 본문(데이터)을 셸 명령과 같은 텍스트로 훑는다.
- **피해**: 이번엔 모델이 `Write` 도구로 우회해 검증 통과(1턴·약 $0.07 손실). 그러나 파이썬·XML·HTML을 heredoc으로 쓰는 거의 모든 작업에서 재발하고, 아침 SUMMARY에 "훅 거부"가 늘 떠서 진짜 위반 신호가 묻힌다(P10). 첫 밤 실측대로 bypass 모드의 모델은 heredoc을 기본 쓰기 채널로 쓴다(findings/001).
- **원인**: findings/001의 해소(heredoc 리다이렉션도 조기 거부)가 본문을 제외하지 않았다. 휴리스틱의 오탐 비용을 "러너가 git status로 최종 판정하니 무해"로 봤지만, 오탐은 거부→우회 턴을 만들고 신호를 오염시킨다.
- **해소** (커밋: 이 파일의 두 번째 커밋, 2026-08-29): ② **heredoc 본문을 스캔에서 뺀다** — `harnesslib.strip_heredoc_bodies`가 `<<[-]?['"]?WORD` 다음 줄부터 `WORD` 단독 줄까지 제거하고 머리 줄(`cat > f <<EOF`)만 훑는다. 단 `sh|bash|zsh|dash|python…|perl|ruby|node <<EOF`처럼 본문이 *실행*되는 heredoc은 본문도 계속 훑는다. `bash_write_targets`(쓰기 대상)와 `pre-tool`의 `check_bash`(commit/push·네트워크 규칙) 둘 다 이 텍스트를 본다. ① `_REDIRECT_RE` lookbehind에 `-` 추가(`->` 제외). 최종 판정은 여전히 러너의 `scope_violations`(git status)라 놓치는 쪽은 안전하다. 이 밤의 실제 heredoc으로 검증: 쓰기 대상 10→1.
- **실측 2 (night-004, 같은 날)**: 6작업 중 task-007에서 거부 1회 — 모델이 렌더 출력을 보려고 `python3 - <<'PY'`(260줄)를 돌렸고, "실행형 heredoc은 본문을 훑는다" 규칙이 파이썬 본문의 `<b>Sentiment</b>`·`> Markets`를 쓰기 대상 10개로 뽑았다. 파이썬 본문의 `>`는 셸이 해석하지 않는다. 해소(세 번째 커밋): 쓰기 대상 추출은 **셸**(sh·bash·zsh·dash·ksh) heredoc 본문만 보고, 거부 규칙(commit/push·네트워크)은 `EXEC_HEREDOC_RE`로 인터프리터 본문까지 본다 — `os.system("git commit")` 같은 우회는 여전히 잡힌다. 검증: night-004의 실제 명령으로 10→0.
- **재발 방지**: `tests/test_harnesslib.py::ScopeTests::test_bash_write_targets_skip_heredoc_bodies`(파이썬 반환 주석·XML f-string·주석 `->`·`<<-` 탭·실행형 heredoc) · `tests/test_hooks.py::test_bash_write_targets_are_scope_checked`(본문 속 줄머리 `curl` 비거부, `bash <<EOF` 안 쓰기·`sh <<EOF` 안 curl 거부).
- **가정 변경**: ASSUMPTIONS 새 행 "heredoc 본문 제외" — 휴리스틱의 오탐도 비용이다.
- **일반화**: 조기 거부 휴리스틱은 "놓치면 러너가 잡는다"로 재현율만 걱정했지만, **정밀도가 낮으면 거부가 곧 우회 유도**가 된다. 데이터(heredoc 본문)와 명령을 구분하지 않는 스캐너는 데이터가 커질수록 오탐이 선형으로 는다.
