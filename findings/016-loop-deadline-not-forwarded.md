# 루프의 남은 시간이 밤 실행에 전달되지 않음

- 발견: Codex 통합 검증의 임시 저장소에서 `night-loop --until-hours 0.01`을 실행했다.
  루프 로그에는 35초가 남았지만 내부 밤의 예산은 기본 8시간이었다.
- 증상: 마감 전에 시작한 밤이 루프 마감보다 긴 모델 실행 시간을 받았다.
- 피해: 검증 당시 큐가 비어 바로 종료됐으므로 초과 실행은 없었다.
  작업이 있으면 지정한 루프 시간을 넘겨 모델을 실행할 수 있었다.
- 원인: 루프가 밤 실행 사이에만 시계를 확인하고 남은 시간을 `runner/night`에 전달하지 않았다.
- 해소: 밤 상한과 남은 루프 시간 중 작은 값을 `--hours`로 전달한다.
  최소 작업 시간보다 적게 남으면 새 밤을 시작하지 않는다.
- 재발 방지: `test_remaining_loop_time_caps_night_budget`,
  `test_shorter_explicit_night_budget_is_preserved`, `test_too_little_time_does_not_start_empty_nights`.
- 가정 변경: 시간 예산은 상위 루프에서 하위 모델 실행까지 전달해야 한다.
  검증·정리는 별도 타임아웃을 사용하므로 프로세스 전체의 강제 종료 시각과는 다르다.
- 일반화: 반복문의 시작 조건만으로는 내부 작업의 실행 시간을 제한할 수 없다.
