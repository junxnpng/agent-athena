# extract v1 구현 완료 기록

사용자 결정: extract 구현을 먼저 끝내고 verify와 실데이터 검증을 함께 수행한다. 이에 따라 원본 계획의 P4a 실제 모델 관측·사람 게이트를 구현 선행 조건에서 후속 인수 절차로 옮겼다. 실제 관측 결과나 사람 승인을 생성하지 않았다.

| 범위 | 구현 상태 | 근거 |
|---|---|---|
| P4b 선택 거부·레코드·보고 계약 | 구현 | 사유 코드·거부 로그, 26키 보고서, 메타데이터 포함 레코드 |
| P4b 다이제스트 | 구현 | 문서 순 정렬, 세 줄 항목, 인용 조각별 페이지, JSONL 재렌더 |
| P5 변형 대조 | 구현 | 설정된 네 변형의 봉인 사본·등급·비정확 행·레이아웃 의심 |
| P5 문단 교차·G 회수율 | 구현 | 원천 위치 오류 차단, 짧은/반복 분리, G 보고 전용 |
| P6 자동 회귀·커버리지 | 구현 | `python3 -S scripts/check-extract`, 줄 커버리지 80% 게이트 |
| 실제 논문·실제 모델·사람 인수 | 대기 | `KVCPOOL` 및 실제 선택 파일 필요 |
| verify 원장 연동·조건 표지 해석 | 후속 sync | verify 완료 뒤 별도 계약 동기화 |

현재 측정: extract 전용 40개 시험 실행, 38개 통과·실데이터 2개 skip. stdlib trace 실행 가능 줄 737/764, 96.5%. coverage.py 수치가 아니며 실데이터 품질 측정도 아니다. 재현 명령은 `python3 -S scripts/check-extract`다.

테스트를 먼저 추가해 기존 구현에서 실패를 확인한 뒤 구현했다. 합성 시험은 두 에이전트 식별자, 선택 없는 실행, 봉인 변형의 변경 거부, 사유별 파일 전체 거부, 페이지 연결과 원문 생략 기호의 구별, G 미회수 시 보고만 하는 동작을 확인한다.

## 내일 함께 확인할 순서

1. 원본 자료 경로를 `KVCPOOL`로 지정하고 `python3 -S scripts/check-extract`를 실행한다. 실데이터 시험 2개가 skip 없이 통과해야 한다. PDF 해시·텍스트·절 제목·연결 인용을 확인한다.
2. 사용자가 작성/확인한 질의로 `segment`를 실행한다. `--title`에 실제 제목을 주고 `--source-root`로 대조 변형을 포함한다.
3. 공통 `extract/SELECTION.md`에 따라 실제 Codex/Claude 세션에서 선택 파일을 만든 후 `build`를 실행한다. 모델명·질의 확인 여부를 정확히 남긴다.
4. 발췌집과 `.run.json`을 검토한다. exact는 텍스트 층에 대한 검사이며 PDF의 시각적 읽기 순서나 의미 충실성 인증은 아니다.
5. `verify/USAGE.md`에 따라 기존 검증 입력으로 실제 검사·판정 왕복을 재현한다. extract JSONL의 원장 직접 import는 아직 제공하지 않으므로 sync 작업을 별도로 수행해야 한다.
6. verify P6/P7 구현·인수 게이트의 미완료 항목을 확인한다. 두 모듈의 테스트 성공만으로 최종 품질 인증을 선언하지 않는다.

## 범위 및 결정

- Python 3.9 stdlib와 시스템 Poppler를 사용한다. 추가 라이브러리·모델 API·스킬 설치를 도입하지 않았다.
- 원본 계획의 `_min` 모듈 이름은 기존 호출 호환성을 위해 유지하되 v1 계약으로 확장했다.
- 빈 선택에는 레코드가 없으므로 빈 다이제스트의 머리는 봉인 workfile과 에이전트 정보로 만든다. 선택이 있는 실행은 레코드만으로 재렌더한다.
- 원문·변형은 export 시 사본을 만들고 해시를 봉인한다. build 시 원본 자료가 달라져도 동일한 사본을 대조한다.
- inbox 배치, API 실행, 조건/수치 추출, 여러 논문 통합 다이제스트는 명세의 v1 이후 범위다.
- 실제 결과 없이 선택 지침을 추측으로 강화하지 않았다. 관련성·kind·메모 품질은 실제 모델/사람 검토에서 확인한다.
