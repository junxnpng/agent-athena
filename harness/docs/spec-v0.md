# 개인 AI 하네스 — spec v0

> [!abstract] 한 줄
> Claude Code / Codex 위에 얹는 **도메인 무의존 하네스 레이어**.
> 퇴근·취침 시점에 한 명령으로 시작해 밤새 무인으로 돌고, 아침에 `SUMMARY.md` 하나로 결과를 파악한다.

## 0. 전제 — 이 spec이 아닌 것

| | |
|---|---|
| **만드는 것** | 하네스 **레이어** — 지침(md) + 훅·스크립트 + 밤샘 러너 |
| **만들지 않는 것** | 하네스 **런타임** — 루프·도구 디스패치·모델 어댑터. Claude Code / Codex가 담당 |
| **규모 감각** | md 수천 줄 + 코드 수백~수천 줄. (참고: superpowers 실측 md 29,322줄 / 코드 11,371줄, 훅은 4파일 122줄) |
| **기존 자산** | 폐기. 기존 68 agents / 41 skills / 41 commands는 재사용하지 않는다. 값어치는 코드가 아니라 실패 기록 |

> [!warning] 핵심 원칙 — 파일 종류가 강제력을 정한다
> **md에 쓴 것은 강제가 아니다. 훅·스크립트에 쓴 것만 강제다.**
> md는 모델이 따를지 정하는 지침이고, 훅은 결정론적으로 실행된다.
> → 부기(bookkeeping)를 md에 쓰면 안 된다. "사이클 번호를 +1 하라"를 md에 쓴 결과가 3주 어긋난 라벨 795곳이었다.

## 1. 확정 사항

| 항목 | 결정 |
|---|---|
| 스코프 | 도메인 무의존. 개인 공부(AI) / 일(AI 연구) / 코딩은 **소비자**이고 하네스 코드에 나타나지 않는다 |
| 단위 작업 | **검증기를 한 번 돌릴 수 있는 최소 덩어리** |
| 접수 게이트 | "이 작업의 검증기가 무엇인가" — 답이 없으면 루프에 넣지 않는다 |
| 예산 | 시간 기반. 밤 창 8~12시간 |
| 분해 깊이 | 리프 **하한 5분 / 상한 30분** · 분해 단계 **상한 3** · 계획에 세부 구현 금지 |
| 제어 흐름 | **부기는 프로그램, 내용은 모델** |
| 실행 | 퇴근·취침 시점 on-demand. cron 상주 아님. 사람 완전 부재 |
| 쓰기 범위 | **대상 git repo 단위. 히스토리도 거기.** |
| 큐 | 하네스 소유. 도메인은 사양만 준다 |
| 분해 | 하네스 소유 |
| 계획의 불변성 | 계획은 **재생성 가능**. 불변인 것은 **실행 이력** |

### 계층 — 5단

```
사양 spec      ← 도메인이 준다. 목표 + 지시문. 유일한 입구
  └ 계획 plan    ← 하네스가 생성. 재생성 가능. 리프마다 검증기가 붙어야 완성
      └ 세션      ← 하네스가 발급 (night-001 …). 밤 하나 = 세션 하나
          └ 작업   ← 계획의 리프. 5~30분
              └ 검증 ← 도메인 검증기. 생성자와 분리된 평가자가 호출
```

### 도메인 계약 — 5개

하네스가 도메인에게 요구하는 전부. 이 다섯 개만 채우면 어떤 작업이든 돈다.

1. **사양** — 목표 + 도메인 지시문
2. **검증기 + 임계값** — 레벨 0(exit code, 필수) / 1(스칼라) / 2(구조화 리포트)
3. **부트스트랩** — 시작 가능 상태로 만드는 스크립트
4. **repo 경로** — 쓰기 범위
5. **특수 도구** — 있으면

완료 조건은 ②의 임계값에 흡수된다. **큐는 도메인 것이 아니다.**

## 2. 리포 레이아웃

### 하네스 리포 (도구)

```
harness/
├─ CLAUDE.md              # 상주 지침. 60줄 이하로 유지
├─ AGENTS.md              # → CLAUDE.md 심볼릭 링크
├─ CONTEXT.md             # 도메인 어휘 + 금지어 + 해소 기록
├─ .out-of-scope/         # 거절 기록 (파일당: 요청 / 이유 / 탈출구 / 과거 요청)
├─ skills/                # 공유 콘텐츠. 모델 호출 위주
│  └─ <skill>/SKILL.md
├─ hooks/
│  ├─ hooks.json          # Claude Code 훅 등록
│  ├─ run-hook            # polyglot 진입점 — 확장자 없음
│  ├─ session-start       # 세션 시작 5단계 강제
│  ├─ pre-tool            # 쓰기 중재 · trifecta 검사 · 예산 확인
│  └─ post-tool           # 병리 카운터
├─ runner/                # 바깥 루프
│  ├─ night               # 진입점: 밤 하나 실행
│  ├─ decompose           # 사양 → 계획
│  ├─ queue               # 큐 + 선택 정책 (아사 방지)
│  └─ id                  # ID 발급
├─ .claude-plugin/plugin.json
├─ .codex-plugin/         # 빌드 산출물. 손으로 고치지 않는다
└─ scripts/sync-to-codex.sh
```

> [!tip] 확장자 없는 훅 이름
> `session-start.sh`가 아니라 `session-start`. Claude Code의 Windows 자동 감지가
> `.sh`가 든 명령에 `bash`를 앞에 붙여버린다. (superpowers `run-hook.cmd` 주석에서 확인)

### 대상 리포 (작업 대상 — 히스토리가 여기 남는다)

```
<target-repo>/
├─ .harness/
│  ├─ spec.md          # 도메인 계약 ①
│  ├─ verify           # 도메인 계약 ② — exit 0 = pass
│  ├─ init.sh          # 도메인 계약 ③
│  ├─ domain.json      # 계약 ④⑤ + 예산 오버라이드
│  ├─ plan.json        # 하네스가 생성. 재생성 가능
│  ├─ log.jsonl        # append-only 실행 이력. 진실의 원천
│  ├─ SUMMARY.md       # 아침 산출물
│  └─ BLOCKED.md       # 막힌 작업
└─ (실제 코드)
```

**`.harness/`는 git으로 추적한다.** 밤 간 인수인계가 `git log`로 된다.

## 3. 컴포넌트 — 무엇이 md이고 무엇이 코드인가

### 프로그램이 소유 (코드 — 모델이 우회 못 함)

| # | 컴포넌트 | 명세 |
|---|---|---|
| P1 | **ID 발급** | 세션 `night-NNN`, 작업 `task-NNN`. **모델이 절대 계산하지 않는다.** 날짜는 메타데이터로만 기록하고 식별자로 쓰지 않는다 |
| P2 | **작업 선택** | 큐에서 뽑는다. 정책 = 아사 방지 + 도메인 점수. **대기 시간이 임계 초과한 항목을 무조건 먼저** |
| P3 | **쓰기 중재** | 멱등 키. 같은 앵커에 두 번 append 금지. 쓰기 범위(계약 ④) 밖이면 거부 |
| P4 | **세션 시작** | 5단계 강제 (아래 §4) |
| P5 | **예산 집행** | 남은 시간 계산. 초과 시 진행 중 작업만 마치고 종료 |
| P6 | **종료 판정** | 모델의 "done"과 별개. 검증기를 돌려 판정한다 |
| P7 | **분해** | 사양 → `plan.json`. 리프 5~30분, 단계 3 이하, 리프마다 검증기 필수 |
| P8 | **막힘 격리** | 막힌 작업을 `BLOCKED.md`로 밀고 **즉시 다음으로 넘어간다**. P2와 같은 메커니즘 |
| P9 | **병리 카운터** | 파일별 편집 횟수 · 연속 실패 횟수 · 조기 종료 시도 |
| P10 | **아침 산출물** | `SUMMARY.md` 생성. 도메인 무관하게 같은 모양 |

### 모델이 소유 (md — 지침)

| # | 컴포넌트 | 명세 |
|---|---|---|
| M1 | 한 작업 안에서 무엇을 어떻게 시도할지 | |
| M2 | 결과 해석 | |
| M3 | 큐 후보 제안 | **선택은 P2가 한다** |
| M4 | 검증 실패 원인 분석 | |

### 스킬 — 모델 호출 위주

무인 실행이면 사람이 슬래시를 못 친다. **`disable-model-invocation`을 쓰지 않는 쪽이 기본값.**
(참고: mattpocock은 22/37이 사용자 호출 — 대화형 전제라 우리와 반대다. superpowers 쪽 14개 방법론 스킬이 참고 모델)

v0 스킬 후보:
- [ ] `verification-before-completion` — 종료 전 사양 대조
- [ ] `systematic-debugging` — 막혔을 때의 절차
- [ ] `writing-plans` — 분해 규칙 (P7이 참조)
- [ ] `session-handoff` — 밤 간 인수인계 작성법

**frontmatter는 2키만 쓴다** — `name`, `description`.
`disable-model-invocation`과 `argument-hint`는 agentskills.io 표준이 아니라 Claude Code 확장이므로 Codex 이식성을 위해 피한다.

## 4. 세션 시작 5단계 — P4가 강제

Anthropic 공개 절차 그대로.

1. 작업 디렉토리 확인
2. `.harness/log.jsonl` 마지막 항목과 최근 커밋 리뷰
3. 최우선 미완 작업 식별 (P2가 결정, 모델이 고르지 않는다)
4. **e2e 스모크 테스트** — `verify`를 한 번 돌린다
5. **기존 문제를 먼저 해결한 뒤** 새 작업 시작

> [!danger] 4단계를 빼면 깨진 코드 위에 계속 쌓는다
> 이건 Anthropic이 명시한 이유다. 훅으로 강제하고 모델 판단에 맡기지 않는다.

## 5. 불변식 — 위반하면 실행 거부

- [ ] **I1** 모델이 카운터·ID를 계산하지 않는다
- [ ] **I2** 실행 이력(`log.jsonl`)은 append-only. 수정·삭제 금지
- [ ] **I3** 컨텍스트는 로그의 파생물이다. 별도 상태로 관리하지 않는다
- [ ] **I4** 실패 흔적과 스택트레이스를 컨텍스트에서 지우지 않는다
- [ ] **I5** 검증기 없는 작업은 루프에 들어가지 않는다
- [ ] **I6** 쓰기는 계약 ④의 repo 경로 안에서만
- [ ] **I7** **lethal trifecta** — 비공개 데이터 접근 · 신뢰불가 콘텐츠 소비 · 외부 통신이 한 경로에서 동시에 성립하지 않는다. 스킬·도구 추가 시마다 재검사
- [ ] **I8** 계획과 진행 상태는 다른 파일 (`plan.json` ↔ `log.jsonl`)
- [ ] **I9** 관측 도구가 관측 대상을 변형하지 않는다 (자기 계측 오염 방지)

### 금지 사항

- md에 부기 지시를 쓰지 않는다
- 날짜를 식별자로 쓰지 않는다
- 에이전트가 자기 스킬을 생성하지 않는다 *(SkillsBench: 자가 생성 스킬은 이득 미미 또는 음수)*
- 쓰기 작업을 병렬화하지 않는다 *(반박 기반 수렴 게이트가 없는 한)*
- 계획에 세부 구현을 쓰지 않는다

## 6. 커밋 정책 — 전역 규칙 예외

> [!warning] 충돌
> 개인 전역 규칙: *"git add/commit/push는 유저가 진행, alias로 차단"*
> 연구: *"서술적 커밋이 체크포인트를 만들어 에이전트가 스스로 되돌려 동작 상태로 복귀할 수 있다"*

**해소**: 하네스 전용 커밋 경로에만 예외를 뚫는다.

- 커밋 단위 = **검증 통과 시점** (작업 하나가 아니라 검증 하나)
- 브랜치 = `harness/night-NNN`. **main·작업 브랜치에 직접 커밋 금지**
- **push 금지.** 로컬 커밋만
- 커밋 메시지에 `[harness night-NNN task-NNN]` 접두어 — 사람 커밋과 구분
- `git alias` 차단을 우회하지 않고, 러너가 쓰는 별도 경로를 만든다

## 7. 아침 산출물 — `SUMMARY.md`

5분 안에 파악되어야 한다. 도메인 무관하게 같은 모양.

```markdown
# night-007 · 2026-08-27 22:14 → 06:02 (7h48m)

## 결론
완료 12 / 막힘 3 / 미착수 8

## 완료 (검증 통과)
- task-041 …  ← 커밋 링크

## 막힘 — BLOCKED.md 참조
- task-044  3회 연속 검증 실패. 마지막 오류: …

## 다음 밤에 할 것
P2가 선택한 상위 3개

## 이상 징후
doom loop 1회 감지 (task-047, 같은 파일 11회 편집)
```

## 8. 멀티 하네스 — Claude Code + Codex

superpowers 방식 그대로. **콘텐츠 하나, 매니페스트 N개.**

- `skills/` 트리 하나를 공유. 하네스별 디렉토리에는 매니페스트만
- `.codex-plugin/`은 **빌드 산출물** — `scripts/sync-to-codex.sh`가 생성. 손으로 고치지 않는다
- `AGENTS.md` → `CLAUDE.md` 심볼릭 링크
- 훅은 하네스별 설정이 전부 `run-hook`을 가리키고 로직은 한 번만 쓴다
- 표준 frontmatter 2키만 사용해 이식성 확보

## 10. 진화 — 컴포넌트별 가정 기록

> [!quote] Anthropic Labs
> *"하네스의 모든 컴포넌트는 모델이 스스로 못 하는 것에 대한 가정을 인코딩한다."*

모든 P·M·I 항목 옆에 **한 줄로 가정과 유효 모델 급**을 적는다. 그러면 모델이 좋아졌을 때 무엇을 지울지가 드러난다.

초기 등록 항목:

| 컴포넌트 | 가정 | 재측정 시점 |
|---|---|---|
| 분해 상한 30분 | 현 세대 모델이 30분 이상 작업에서 일관성을 잃는다 | 모델 메이저 업데이트 |
| P9 doom loop 탐지 | 모델이 같은 실패를 반복해도 스스로 접근을 바꾸지 않는다 | 동일 |
| P4 4단계 스모크 | 모델이 기존 상태를 확인하지 않고 새 작업을 시작한다 | 동일 |
| P6 종료 판정 | 모델이 자기 작업을 과대평가한다 | 동일 |

**폐기 리듬**: 모델 메이저 업데이트 때마다 위 표를 훑고, 가정이 무너진 컴포넌트를 **지운다**. 삭감 절차가 없으면 하네스는 단조 증가한다.

## 11. 근거 표시 — 출처 등급

spec 항목의 근거 강도를 구분한다. 나중에 뒤집을 때 판단 기준이 된다.

| 등급 | 의미 | 해당 항목 |
|---|---|---|
| **A** | 독립 출처 4개 이상 | 파일·git에 상태 저장 · 계획/실행/평가 분리 · 분해는 하네스 소유 · append-only |
| **B** | 실측 근거 있음 | 세션 시작 5단계 · doom loop 탐지 · 자기 검증 강제 · 추론 예산 배분 · 스킬 크기 · 자가 생성 스킬 무효 |
| **C** | 단일 출처 또는 벤더 발표 | 쓰기 병렬 + 수렴 게이트 · 이벤트 도메인 3분류 · 설정 레이어링 |
| **D** | **연구 근거 없음 — 개인 경험** | **아사 방지(P2) · 자기 계측 오염(I9) · 밤 계층** |

> [!important] D 등급 셋
> 외부 연구 코퍼스에 없다. 62사이클 무인 루프에서 직접 겪은 것이라 넣을 근거는 충분하지만,
> **일반 원칙으로 착각하지 않도록 등급을 표시해 둔다.** 다른 사람에게 권할 때는 이 표시를 같이 준다.

## 12. 나중에 — v0 범위 밖

`.out-of-scope/`에 파일로 옮길 후보. 각각 **이유 · 탈출구 · 요청 이력**을 함께 적는다.

- 웹 UI / 대시보드 — 밤샘은 headless. 아침 산출물이 md 하나면 충분
- 실시간 알림 — 자고 있으므로 무의미
- 쓰기 병렬화 — 수렴 게이트를 만들 때까지 보류
- 외부 스킬 레지스트리 설치 — 심사가 없고 조사에서 26.1%가 보안 문제. vendoring한 것만
- 벡터 DB / 그래프 인덱스 — grep + 파일이 기본값. 관계 질의가 병목이 되면 재검토
- 메모리 런타임(mem0/Letta) — 파일로 시작. git diff가 되는 것 자체가 디버깅 도구
- 규제 대응(EU AI Act Annex III) — 개인 용도라 해당 없음. **회사 업무를 넣게 되면 즉시 재검토**
