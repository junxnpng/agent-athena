## 세 차단 항목의 닫힘 확인 (원문 대조)

1. **elusion — 닫혔다.** plan:80이 표집 프레임을 처음으로 명문화했다: 미사용 문단 = 전체 블록 − `claims` 행의 인용이 해결된 블록, 격리 레코드의 fragment는 「사용」으로 세지 않음. P1 말미에 `paragraphs.py`와 두 변환기가 모두 존재하므로 실제로 세어 `elusion_n`을 풀 이하로 등록한다는 순서도 맞다. plan:125는 달성 가능한 상한만 적고, V3-3은 「풀 크기 출력 → `elusion_n ≤ 풀` 표집 → 상한 보고 → 재표집 시 종료 코드 1 → 5% 도달 불가 명시」로 재작성됐으며, Deferred(plan:237)가 5%에는 n≥59가 필요하고 k>1에서만 가능함을 적었다.
2. **κ 짝짓기 — 닫혔다.** plan:136의 라벨 대상이 「P3가 tier1에 태운 것과 같은 행 집합(20행, 가능하면 L1 PASS 51행 전부)」이 됐고, κ는 행 단위로 짝지으며, G 문장은 재현율 기준으로만 쓴다. B-2(plan:188)에 `unpaired labels`로 죽는 실패 모드까지 들어갔다. `gold_labels.tsv`의 sha256 봉인도 반영됐다.
3. **B-1 정답 문장 수 — 닫혔다.** plan:124가 `**`/`****` 분리를 규칙 첫 항으로 올렸고, 메모 종료 지점 규칙을 추가했으며, 등록 수치는 규칙 산출값으로만 적고 임시 계수를 쓰지 않는다. B-1(plan:187)이 「하드코딩 금지, `gold_split_count`로 기록」 + 첫 문장 생존 + 메모 혼입 0건으로 바뀌었다. B-1도 P5로 옮겨져 산출 단계와 시험 단계가 일치한다.

## 40개 불릿 전부 RUNNABLE 또는 SCENARIO인가 — 그렇다

`[R]` 33 / `[S]` 7이고 단계 배정도 5+5+5+3+5+14+3 = 40/40이다. iteration 2에서 NOT TESTABLE로 분류했던 셋(V3-3, B-2, B-1)이 모두 시험 가능해졌고 공허한 불릿은 남지 않았다. C0-2의 수치가 자기 정합적이다: 0건 2 + 1건 14 + 2건 12 + 3건 2 = 레코드 30, 인용 0+14+24+6 = 44(원 레코드 30·37은 직접 세어 확인).

## 두 표기 항목은 차단하지 않는다 — 다만 셋이다

아키텍트의 둘(「실측 38」을 P1 측정이 등록하는 참조값 35–38로 표기 / 미사용 문단 정의가 spec:94 문언보다 좁다는 한 절)은 모두 비차단이다. 전자는 V3-3의 시험 명제가 `elusion_n ≤ 풀 크기`라 실측값이 38이 아니어도 참이므로 모순이 아니고, 후자의 좁힘은 시스템에 불리한 쪽이다(풀이 커지고 놓침을 찾을 기회가 늘어난다).

하나 더, 역시 비차단: ADR plan:217이 아직 "사람 라벨 33건(30분)을 새로 받되"라고 적는다. plan:136·188이 확정한 「P3가 태운 행 집합 20~51행」과 어긋나는 iteration 2의 잔재다. 실행 계약(단계 지시문·AC)에는 33이 남아 있지 않으므로 새 라운드 사유는 아니며, 커밋 전 같은 편집에서 `20~51행`으로 고치면 된다.
