# Decisions (v1)

- **NLI backend.** The first sweep is a stdlib lexical router (tier0, can never emit `supports`) followed by a mid-size judge over a file round trip (`judge export` / `judge import`). Local NLI models and small API models stay as interface stubs until the corpus grows past the gold paper (≈1,900 rows).
- **Row unit.** One quote is one row, `row_id = <extractor>:<record_id>.q<n>`. A Codex record yields a row only when it has exactly one fragment; every other record closes as quarantine with a reason code, so the source record count always closes.
- **κ is report-only.** Judge agreement with human labels is reported with a bootstrap CI and never gates: at 20–51 rows a judge with true κ≈0.85 fails a 0.7 gate about half the time.
- **Quote-to-block resolution.** A quote resolves into a paragraph block by a contiguous canonical match of one of its pieces (every occurrence) or by sharing at least two 8-word shingles with the block; one shared shingle is a repeated phrase, not the quote. The shingle path is needed because the raw extraction interrupts quotes with figure labels: 6 of 51 gold-paper rows resolve only this way, and every shingle-only hit was read and shares 8–59 shingles with its quote (a continuation of the same passage). `locator.para_id` is the first contiguous hit, else the first shingle hit; `resolved_para_ids` keeps them all. On the gold paper: frame 70, used 36, unused pool 34, registered as `elusion_n: 34` (the plan's reference range was 35–38; the substring-only reading gives 40 with 6 rows unlocated).
- **Unlocated rows are not quarantined.** A row whose quote resolves into no block keeps `para_id: null`; whether the quote exists is the existence check's decision against every variant, not the converter's. `locator_unresolved` is reserved for records with neither page nor location.
- **Sealed paragraph unit.** The paragraph unit lives in `config/thresholds.yaml` and is read before registration (conversion needs it), so each converter output records the unit it used; import refuses a unit that differs from earlier imports of the paper or from the registered file, and registration refuses a file whose unit differs from the imported rows'. After registration every reader goes through the guard on the registered file.
- **Default query needs confirmation.** `config/queries/gold-kv-reuse.yaml` is an agent draft; `confirmed_by` is empty and `queries.require_confirmed` refuses it, so judging against it waits for the user to confirm or rewrite it (under a new id, since a registered id cannot change).
- **Kind mapping.** `config/kind_map.yaml` maps free-form labels by the earliest listed label in the string. `기전 설명` and `방법 설명` (author's description of mechanism/method) map to `author_interpretation`; `2차 인용` and `합성 설정` alone are left unmapped and quarantine as `kind_unmapped`. A compound label takes its first component (`실제 관측 + 저자의 해석` → `measurement`); `source_kind` keeps the full label, so an interpretation component is recoverable but not counted by `kind`.
- **Existence check matching.** A quote is split into pieces at elision marks (`…`, `...`, `[...]`, `**`, `|`), and the pieces must occur in order in one variant; the span is the shortest such embedding. There is no gap tolerance between the characters of a piece. The grade is the strictest of exact / strict (the six rules of `config/normalization.yaml`) / loose (the old alphanumeric canon) at which every piece matches; the row takes its best grade over the variants, ties to the earlier variant in `config/sources.yaml`. A PASS row carries `matched_variant` and the span; a MISS row carries neither, which a trigger enforces. The latest L1 check of a row decides, and a row never checked is not passed.
- **Gold paper L1, protocol v1 (measured 2026-09-23).** Claude 44: exact 0, strict 29, loose 9, MISS 6. Codex 7: exact 2, strict 4, loose 0, MISS 1. PASS 44, MISS 7.
  - The 6 Claude MISS rows (`YR-B1.q1, YR-C2.q1, YR-E1.q1, YR-G3.q1, YR-H2.q1, YR-H4.q2`) are the rows the paragraph locator resolved only by shingles: the quoted passage is in the text, but a running header, a figure block or a page break sits inside it, so no piece matches contiguously. They were false negatives of the check, not missing quotes.
  - 8 of the 9 loose Claude rows fail strict only because the extraction already dropped a line-end hyphen (`platform-hosted` → `platformhosted`, `state-of-the-art` → `stateof-the-art`); the 9th has scattered math subscripts. The hyphen rule joins `infer-\nence`, but it cannot restore a hyphen the text no longer has. It was not widened after measuring.
  - Codex rows are not tautological for all 7: `YR036.q1` begins with the section number `8`, which the raw text places elsewhere. `l1_tautological` stays a property of the record type; the one MISS is reported, not excused.
  - `codex_layout` sets the two columns side by side on one line, so a multi-line quote cannot match it contiguously.
- **Gapped grade, protocol v2 (user decision, 2026-09-23).** After the v1 measurement the user chose to accept false positives in v1 rather than reject genuine quotes interrupted by foreign text. A fourth pass grade `gapped` matches the loose form of each quote piece as at most 3 runs of at least 20 characters with at most 1,000 original characters between runs; every character of the quote is still matched in order. The parameters were chosen after seeing the 6 rows (their intrusions are 60–586 characters in `claude_body`), so they are a post-measurement protocol change, registered as `protocol_ver: v2` (`l1_pass_grades: [exact, strict, loose, gapped]`, sha256 `7a79a963a011…`) beside the v1 registration, which stays in the ledger. Verifier `l1-exists-v2`.
  - Gold paper under v2: Claude 44 = exact 0, strict 29, loose 9, gapped 6, MISS 0; Codex 7 = exact 2, strict 4, gapped 0, MISS 1 (`YR036.q1`: its first run is a 3-character accident, under the 20-character minimum). PASS 50, MISS 1. In `codex_layout` one short quote split across a column line now matches as gapped (`YR-A1.q1`, loose elsewhere).
  - The risk accepted: a fabricated quote assembled from up to three real 20+ character runs within 1,000 characters of each other would pass. Mutation tests (P6, `quote_word_swap`) measure how often that happens.
  - Registering a second protocol version used to fail, because counting the unused pool read the paragraph unit through the not-yet-registered file; registration now counts the pool with the candidate file's unit.
- **Waiver reason codes.** `config/waiver_reasons.yaml` maps a free-form reason to the code of the earliest mechanism it names; `visual_check` applies only when no mechanism is named; an unmapped reason is refused. The 48 waivers of `claude_verbatim_waivers_strict.tsv` take 5 codes: italic_reorder 32, stamp_intrusion 9, gap_exceeded 5 (MAX_GAP and greedy-duplicate matches), column_interleave 1, visual_check 1 (a split identifier); `ligature` is defined but unused. Waivers are per quote, so `waiver_rate` is reported as rows: gold paper 0/44, overall 48/1489 quotes, with the record-level pair (46/804 records) beside it. The plan's `48/804` divided quotes by records.
- **Later layers read `v_l1_passed`.** `ledger.l1_passed(conn, paper)` is the only row source for L2, L6, the judge and recall; `test_miss_blocks_downstream.py` checks each of those modules, once written, reads through it and never selects from `claims`.
- **Query form: any claim against every row.** A query is run input, not system knowledge: the judge asks whether each L1-passed row supports, refutes or is insufficient for one claim, whatever the topic. Taking the pattern page's own claims (P0–P8, with their cited records) as queries was considered and rejected as the primary form: it only audits claims someone already wrote, while the system must answer for a new claim. It stays possible later as a citation audit on top of the same round trip. The slice runs on `gold-kv-reuse-v2` ("Production LLM serving traffic reuses prompt prefixes across requests."), a system-test query chosen to be one claim that only part of the paper addresses; the user approved it in session. The first draft `gold-kv-reuse` stays registered and unconfirmed.
- **Tier0 routes, it never judges.** `backends/lexical.py` (`lexical-v1`, `config/lexical.yaml`) sends a row to the judge when it shares at least 2 stemmed content words, a number or a proper noun with the query (topic + claim); otherwise the row is `insufficient`. Its only outputs are `insufficient` and `needs-judge`, and a trigger refuses any other tier0 verdict. The sweep, like the export, needs a confirmed query. How many relevant rows tier0 drops is the leakage test of P6.
- **Judge verdict storage.** Alignment and faithfulness are two `checks` rows per item (`layer` `align` / `faith`) with `tier` (`tier0`/`tier1`/`tier2`) and `query_id` columns, added to old ledgers by `init`. `v_alignment` gives, per row and query, the highest tier's latest verdict; `v_judgments` pairs alignment and faithfulness of one import as two columns. A trigger closes the verdict set and requires a resolved span (variant, offsets, non-empty text) for supports/refutes.
- **Export and import.** The export takes the tier0 `needs-judge` rows in the order of `sha256("<sample_seed>:<row_id>")`, up to `--limit`, with the paragraph block(s) around the L1 span as context (`quote`, `para`, `para1`), and alternates query/evidence order with `--swap-order`. Any string ending in `.pdf` stops the export. The file's sha256 is written beside it and sealed in `runs`; the import refuses a manifest that differs from the file or from the sealed value, a line count that differs from the items, a line whose item or row_id does not match, a verdict outside the closed set, a supports/refutes without a span, and a span that does not resolve in the context and, at the same absolute offsets, in the variant text. The judge's protocol is the `protocol_ver` of `skills/claim-judge/SKILL.md` (`claim-judge-v1`), recorded in the export and required on import.
- **Judge model.** The mid tier of the slice is a Claude Sonnet 5 subagent in a fresh context that sees only the skill and the export. It is the same model family as the Claude extractor; the spec allows that when `verifier_id` says so, and the report shows the verifier.
- **No budget gate; plan usage is reported (protocol v3, user decision 2026-09-23).** The caps on tokens per record, wall clock and expensive-call ratio are removed from `config/thresholds.yaml`; cost never fails a run. Instead the judge round trip records the plan's 5-hour usage before (`judge export`) and after (`judge import`) and reports the difference in percentage points. The value is read from the usage cache the user's statusline already keeps (`/tmp/.claude-usage-cache.json`, refreshed about every 2 minutes; its source is the plan usage endpoint the statusline queries, not a documented interface). It is account-wide, so concurrent sessions count too; a window reset between the two snapshots gives `reset during run`, a snapshot older than 5 minutes is marked stale, and an unreadable cache gives `unavailable` without stopping the import. The documented path to the same value is the statusline's stdin `rate_limits`; switching to it would mean changing the statusline.
- **L2 schema and tags.** `l2_schema.py` (`l2-schema-v1`) runs the contract validator of `schema.py` on each L1-passed row as the ledger holds it (quote, claim_text, kind, conditions, numbers), so a missing condition key, a number without value / unit / definition / derived_from, or a kind outside the three tags quarantines the row; nothing is filled in. Two lexical rules are added: a row whose quote or claim carries a comparison marker (`config/comparison.yaml`) cannot have `baseline: "none"`, and a claim more certain than its quote on hedged < plain < universal (`config/modality.yaml`; English markers as whole words, Korean as substrings) is `modality_raised`. Any reason quarantines and makes the row not comparable. Reasons are stored comma-joined in `checks.reason_code`, so a mutation that adds a reason is detected even when the verdict was already quarantine.
  - Gold paper: 50 of 50 quarantined (the prior expectation; the rate is labelled an input diagnostic), `missing_condition_field` 50, `missing_number_field` 47, `modality_raised` 6. Two of the six are lexicon false positives (`appears` meaning "shows up"); four are a `may` clause in a long quote that the claim does not restate, because the flag compares whole texts, not aligned clauses. The lexicon was fixed before the run and not changed after it.
- **L6 arithmetic.** `l6_arith.py` (`l6-arith-v1`) has four parts. (1) A contract number whose `derived_from` is an expression over numbers, `+ - * / **` and `ratio`, `pct_change`, `mean`, `geomean` is evaluated through a whitelisted AST (no names, no attributes) and must match its value within half a unit of the value's last printed digit; `mean` over `ratio` terms is flagged as `ratio_arithmetic_mean`. (2) Free number strings are parsed for numbers, superscript powers, K/M/B suffixes and units (`config/numbers.yaml`), and `a op b ≈ c` inside a string is recomputed. (3) Keyed values (`label = value`, `label ≈ value`, not lists or arithmetic operands) are converted to a base unit and compared across different records of the paper; two values that differ by more than both printed precisions are an `intra_doc_conflict` pair. Rows of one record share their numbers and never conflict with each other. (4) For Codex rows, the source record's fragment sha256 must match the fragment text and the quote, and the fragment's loose form must occur in `codex_raw` or `codex_layout` (the old `codex_verify_metric_sources.py` did this per PDF page with pdftotext; here it is the registered whole-document texts). Part 4 needs the source root and is skipped without it.
  - Gold paper: `applicable_rows: 0` for derived_from (the prior expectation). 47 rows carry number strings, 43 of them parse to at least one value (337 values); 15 rows say the value is not reported and 2 that the arithmetic is the extractor's. The one inline computation (`35,795,761 / 2,522,394 ≈ 14.2`) is consistent. 8 keyed values, 0 conflicts. Codex: sha256 6/6, raw 5/6, layout 0/6; `YR023.q1` is in neither because its fragment begins with the section heading `6.3 Cache Simulations`, which the raw text places elsewhere. L1 passed it in `claude_body`, so it is a row where the existence check and the fragment check disagree, reported as a flag, not excused.
- **Statistics are stdlib.** `stats.py` computes exact binomial bounds by bisecting the binomial CDF instead of a beta quantile, kappa with `None` when chance agreement is 1, a percentile bootstrap from `random.Random(seed)` that skips resamples whose statistic is undefined and reports how many were valid, and Chapman's estimator. The elusion bounds the plan quotes are one-sided 95% (`upper_bound(0, n)`); `clopper_pearson` is the two-sided interval.
- **Gold split.** `convert/gold.py` splits the pasted line of G by the rules of `config/gold_split.yaml` (`gold-split-v1`), and the sentence count is whatever the rules produce, recorded as `gold_split_count` in the `gold-register` run. Runs of `**` separate the heading (not gold), the one-line review (one user note) and the body. Body text ends a sentence at a period followed by a capital (abbreviations excepted), at a `->` or at the end of the line. A note runs from `->` to the earliest of three boundaries: a period plus a capital, a lower-case letter glued to a capitalized word (`promptsOutput`; names such as `DeepSeek` excepted), or a lower-case letter, a space and a listed sentence opener (`opportunities While`). A sentence split out of text glued without a space has `boundary_repaired=1`; `**` and `->` are markers, not repairs. Gold paper: 40 sentences (24 repaired), 6 notes. Four of the five `->` notes are paper sentences the user copied and marked as notes; the rules follow the user's markup and do not turn them back into gold. The registration seals the split's sha256: the same file again is a no-op, a different split is refused, and a revision goes through an audit.
- **Gold recall matching.** A row covers a gold sentence when their canonical forms (citations dropped, alphanumerics only, so `inferencesystem` equals `inference system`) share runs of at least 40 characters (the whole sentence when shorter) that cover half the sentence (`config/recall.yaml`, `recall-v1`, fixed before the first run). On the gold paper the result does not depend on these values: the 23 covered sentences have coverage 1.0, and none of the 17 missed ones shares more than 23 contiguous characters with any quote. Recall = gold sentences matched / gold sentences; precision = rows matched / L1-passed rows of the set, a lower bound because G is a hand pick, not an exhaustive extraction.
- **numbers_match and conditions_match.** numbers_match asks whether a covering row's own number strings contain every number of the gold sentence (read with the L6 grammar after citations, figure/section references in any case and model version tags are removed; `10^2` reads as 10²). The first run read the lower-case `figure 4b` as the number 4; the pattern was fixed with a test and the ledger rebuilt from the pre-recall copy before the recorded run. conditions_match is not-applicable: G carries no condition labels and no row carries the five condition fields, and none is derived.
- **Recall reads rows through the view; the elusion frame stays the registered one.** Recall takes its rows from `ledger.l1_passed` only, so the Codex column has 6 rows, not 7. The elusion pool is still `ledger.unused_pool`, the frame counted at threshold registration (blocks no delivered row resolves into), so the blocks of the one L1-MISS Codex row count as used; changing the frame after registration would change a registered number.
- **Elusion sample.** `recall --elusion-export` draws `elusion_n` blocks with `random.Random(sample_seed)` from the sorted pool, once per paper and set of extraction runs; a second draw is refused (`resampling forbidden`, exit 1) before any file is written. The TSV and its sha256 are recorded in a run. On the gold paper n equals the pool (34), so the sample is the whole unused pool. The review is imported once (`--elusion-import TSV --reviewer NAME`), with every sampled block given a missed-claim count; k is the number of blocks with a miss and the bound is one-sided exact binomial. Before review the achievable 0-error bound (8.4%) is reported with the note that 5% needs n ≥ 59.
- **Gold floor on the elusion review.** The gold sentences no row covers are located in the paragraph unit: 6 sit in 3 unused-pool blocks, which are all sampled, so a review that counts them gives k ≥ 3 and a bound of at least 21.3%, not the achievable 8.4%. The other 11 sit in blocks another row already uses; block-level elusion cannot see a missed sentence in a used block, so gold recall, not elusion, measures those.
- **Capture-recapture.** The capture unit is a frame block resolved by an L1-passed row. Chapman's estimate needs two extractor sets, the smaller at least `min_size_ratio` 0.5 of the larger in rows (`config/recall.yaml`; `thresholds.yaml` is sealed and a new key would need a new protocol version). The v1 Codex set holds only single-fragment records, 6 rows against 44, so the estimate is skipped as asymmetric. It is always labelled `lower_bound: true`.
