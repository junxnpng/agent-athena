# AI 산출물 검증 시스템 설계 — 주장 원장(claim ledger) 기반 (2026-09-22)

> **위치 (2026-09-22 이전).** `/work/jun/AI-helper/verify/`(jun-heo/AI-helper) 기준 상대 경로. `$KVCPOOL`=`/work/jun/priv-mb-eval/kvcpool-trace-gen`은 입력 데이터가 남아 있는 원 저장소다.

「40편을 읽고 KV 캐시 특성 주장을 다 찾아 정리해 달라」 같은 논리 작업을 AI에 맡길 때, 그 결과를 시스템적으로 검증하려면 무엇을 만들어야 하는가. [`refs/verification-methods-2026-09-21.md`](../refs/verification-methods-2026-09-21.md)(학술 방법론)와 [`refs/verification-voices-2026-09-21.md`](../refs/verification-voices-2026-09-21.md)(2026년 발언·실증)의 근거를 하나의 설계로 접었다. 근거 표기는 두 문서의 출처명을 그대로 쓴다.

## 0. 한 문장

**AI가 만든 것을 사람이 다시 읽는 시스템이 아니라, AI가 「검사 가능한 모양」으로만 산출하게 강제하고, 그 산출물을 결정론적 검사 → 통계적 재현율 추정 → 독립 재추출 대조 → 보정된 심판 → 크기를 정한 사람 표본의 순서로 통과시키는 시스템을 만든다.** 검사기 자체도 오류 주입으로 검증하고, 통과 기준은 실행 전에 등록한다.

## 1. 설계 원칙

| # | 원칙 | 근거 |
|---|---|---|
| P1 | **산출물 모양이 검증을 결정한다.** 모든 주장은 원문 인용 문자열 + 위치 + 조건 + 수치 + 성격 태그를 갖는 레코드로만 존재한다. 자유 산문은 레코드를 가리켜야만 쓸 수 있다. | Husain 2026(검증이 어려우면 제품 결함, 답은 provenance), Elicit·Claude Science(문장 단위 출처), ScientistOne Chain-of-Evidence, Shankar 2026(범주에도 소속 레코드·역참조) |
| P2 | **존재 검사와 지지 검사는 다른 층이다.** 인용이 실재한다는 것과 그 인용이 주장을 지지한다는 것을 따로 잰다. | Onweller 2026(링크 유효 94%↑, 사실 정확도 39–77%), Walters & Wilder 2023(실재 인용의 24–43%에 실질 오류) |

| P5 | **두 번째 모델은 독립 검증이 아니다.** 모델 심판은 선별(triage)이고 판정은 사람 표본과 결정론적 검사가 낸다. 심판은 사람 라벨로 보정한 뒤 단일 최고 심판을 항목 단위로 쓴다. | Kohli 2026(9심판=2표), Kim 2026(AI 겹침 21% 대 사람 3%), Norman 2026(일치율은 κ보다 33–41pp 과대), Dorner 2024(심판이 모델보다 정확하지 않으면 사람 라벨을 반 이하로 못 줄임), Wang 2023(순서 편향) |
| P6 | **검사기는 생성기가 고칠 수 없는 자리에 두고, 검사기도 검증한다.** 오류를 심어 검출률을 재고, 모델이 바뀌면 다시 잰다. | Karpathy autoresearch(채점 파일 수정 금지), Tao Dwarkesh(RL은 뒷문을 찾는다), sciwrite-lint·Nguyen 2026(오류 주입 벤치), Wang 2606.26300(검증기는 생성기와 함께 진화) |

| P8 | **맞음과 이해와 가치는 따로 묻는다.** 최종 게이트는 「검증자가 이 표로 발표할 수 있는가」다. | Tao ICM 2026(발표 문턱, 증명 소화불량), Buzzard 2026(충실하나 무가치), Mollick·Lahlou(검증 능력은 영역 지식에 묶임) |

## 2. 시스템 개요

### 2.1 파이프라인

```
[0 사양·정답 심기]  스키마 · 통과 기준 · 정답 세트 G · 탐침 P · 목표 집합 T   ← 사람이 쓴다. 실행 전 고정.
        │
[1 생성]  추출기 A ──┐  문단 단위 입력, 같은 스키마, NEI 허용, 전 과정 로그
          추출기 B ──┤  (다른 모델 계열, 서로 못 봄)
                     ▼
[2 기계 검사]  L1 존재·포함(인용 문자열 ∈ PDF, 위치 해결)      → 실패 = 즉시 기각
               L2 스키마·태그 완결(조건 5필드, 단위, 기준선)   → 미완 = 격리
               L6 산술·문서 내 일치(재계산, 초록 대 본문)       → 불일치 = 격리
                     ▼
[3 재현율]  G 대비 재현율 · P 회수 · T 회수 · A/B 포획-재포획 · 미사용 문단 elusion 표본 · 반복 실행 대칭차
            미달 → 잔여 문단만 재추출(논문 통째 금지) → 다시 3
                     ▼
[4 교차 판정]  A/B 행 짝짓기 · 필드 diff · Krippendorff α + 부트스트랩 q · 불일치 = 사람 감사 대기열
                     ▼
[5 충실성·귀속]  NLI 전수 스윕(SUPPORTS/REFUTES/NEI + 근거 스팬) → 보정된 단일 심판(순서 교대, Unknown 허용) → 3분류 귀속 태그
                     ▼
[6 조건 드리프트]  종합 문장마다 링크된 레코드 존재 · 조건 포함 관계 · 확신 표지 diff · 구체성 태그
                   (재정리·요약을 한 번 할 때마다 다시 돌림)
                     ▼
[7 비교가능성]  최소 태그 5개 강제 · 기준선 없는 값은 비교표 진입 금지 · 교차 논문 충돌 3분류
                     ▼
[8 사람 감사]  층화 표본(고위험·불일치·심판 플래그·무작위), 크기 사전 고정, 정답 섞기, 감사자 정확도 측정
                     ▼
[9 검증기 검증]  오류 주입 → 각 검사기의 검출률·오탐률 · 심판 κ·위치 편향 · 모델 판마다 재측정   (2~8에 병렬)
                     ▼
[10 출시 게이트]  사전 등록 기준 전부 충족 · 출처 묶음 봉인 · 검증자 발표 가능성 확인
```

### 2.3 구현 형태: 무엇을 코드로, 무엇을 스킬로

이 시스템은 「스킬 하나」가 아니다. 검증의 무게는 결정론적 코드와 원장에 있고, 스킬은 LLM이 개입하는 층의 프롬프트 묶음과 진입점이다. 검사기가 생성기의 쓰기 범위 밖에 있어야 한다는 원칙(P6)은 스킬로는 지킬 수 없다. 스킬은 모델이 읽는 지시문이고, 모델이 고치거나 무시할 수 있기 때문이다.

| 층 | 형태 | 이유 |
|---|---|---|
| 원장, L1 존재, L2 스키마, L6 산술, 재현율 추정, α, 드리프트 diff, 오류 주입, 게이트 | **Python 패키지 + SQLite**(`tools/verify/`, CLI 하위 명령) | 결정론적이어야 하고, 실행 이력이 남아야 하고, 모델이 못 고쳐야 한다 |
| 추출기 A/B, NLI 후 심판, 독립 검증 질문, 조건 질문 | **스킬**(`~/.claude/skills/claim-extract`, `claim-judge`) 또는 에이전트 정의 | 프롬프트·스키마·순서 교대 규칙을 재사용 가능하게 묶는 자리. 출력은 원장에 쓰고, 판정은 코드가 한다 |
| 40편 병렬 추출, A/B 동시 실행 | Workflow 스크립트 또는 Agent 병렬 호출 | 팬아웃만 맡고 결과는 원장으로 |
| 파이프라인 진입점, 보고서 생성 | **스킬**(`verify-run`) | 「어떤 순서로 어떤 스크립트를 부르는가」를 사람이 매번 기억하지 않게 |
| 출시 차단 | 훅(Stop 또는 빌드 전 PreToolUse)에서 `gate.py` 호출 | 게이트 미달이면 페이지 빌드가 안 되게 하는 강제 장치 |
| NLI 1차 스윕 | MiniCheck급 소형 모델(로컬 또는 API) | 전수 스윕은 값싸야 한다. 심판 LLM은 플래그 행에만 |

**이것이 검증 시스템인가.** 그렇다. 다만 두 가지를 분명히 한다. 첫째, 생성 단계에 제약(스키마, 독립 이중 추출, 문단 입력)을 두는 이유는 검증을 위해서다. 검사 가능한 모양으로 나오지 않은 산출물은 검증할 수 없기 때문에 생성 제약은 검증 시스템의 일부다. 둘째, 이 시스템이 보증하는 것은 원문에 대한 충실성, 완결성(재현율), 문서 내 일관성, 조건 보존까지다. 결론이 참인지, 가치가 있는지는 보증하지 않는다(P8). 그 둘은 사람의 영역 지식과 동료 심사의 몫이다.

## 3. 구성 요소별 사양

각 항목: 입력 → 검사 → 출력·게이트 → 근거 → 이 프로젝트의 기존 도구.

### 3.1 사양·정답 심기(실행 전, 사람이 쓴다)

- **스키마 고정.** 위 `claims` 필드. 조건 5필드(세는 단위, 분모 모집단, 관측 창, 이상/실측, 기준선)는 값이 없으면 「없음」이라고 명시해야 통과한다. 성격 태그는 measurement / author_interpretation / extrapolation 셋.
- **정답 세트 G.** 40편 중 k편(예: 3편)을 사람이 스키마대로 전부 손으로 추출한다. 이것이 재현율·정밀도의 기준이다. Ng의 「evals 먼저」, Anthropic의 coverage check가 이 형식이다.
- **탐침 P.** G의 일부를 코퍼스 어디에 있는지 기록만 해 두고 추출기에는 알리지 않는다. 회수율이 곧 재현율의 직접 표본이다(Oleson 2011, Chen 2608.01000).
- **목표 집합 T.** 사람이 무작위로 고른 「반드시 잡혀야 할」 스팬 10개. 10/10 회수면 95% 신뢰로 recall ≥ 0.7(Cormack & Grossman target method, Stevenson & Bin-Hezam 경유).
- **통과 기준 등록.** §4의 임계값을 실행 전에 파일로 적고 해시를 남긴다. 통과할 때까지 재표집하지 않는다(Lewis 2021).
- **「좋은 표」 정의 문서.** autoresearch의 `program.md`처럼 사람이 소유하고 생성기는 읽기만 한다.

### 3.2 생성(독립 이중 추출)

- 다른 모델 계열 둘(또는 같은 모델의 독립 설정 둘)이 **서로의 출력을 보지 못한 채** 같은 스키마로 추출한다. 「한쪽이 뽑고 다른 쪽이 검토」는 열등하다(Buscemi 2006, 상대 오류 21.7%↑). 두 추출기의 독립은 3층 포획-재포획의 전제이기도 하다.
- **문단 단위 입력.** 논문 통째가 아니라 문단·절 단위로 넣는다(Konet 2024: 발췌 입력이 98.7–100%; Tan & D'Souza 2026: 긴 컨텍스트가 튜플 결합을 악화).
- **NEI 허용.** 「조건을 확정할 수 없으면 판정 불가로 남겨라」에 감점을 두지 않는다(Kalai 2026: 표준 채점에서는 추측이 우세 전략; Claimify의 Cannot be disambiguated).
- **로그.** 프롬프트·모델 판·입력 해시·원 출력을 `runs`에 남긴다. 나중의 모든 수치는 run_id에 묶인다.

### 3.3 기계 검사층(결정론적, 생성기가 고칠 수 없음)

- **L1 존재·포함.** `quote`가 해당 `paragraphs.text`에 문자열로 존재하는가(공백·하이픈·따옴표 정규화 후 정확 일치). locator가 해결되는가. paper_id·DOI가 해결되는가. **전수, 실패 = 기각.** 기존 `$KVCPOOL/tools/quotes_verbatim_check.py`가 이 자리다. 현재 33건인 waiver는 사유 코드가 있는 구조화 예외로 바꾸고, waiver 비율 자체를 지표로 본다.
- **L2 스키마·태그.** 조건 5필드 존재, 수치에 단위·정의, 비교 행에 기준선, 성격 태그. **미완 = 격리**(비교표 진입 금지). SoK D1(기준선 없는 절대값은 비교 불가), REFORMS 체크리스트에서 필드명을 빌린다.
- **L6 산술·문서 내 일치.** `derived_from`이 있는 수치는 재계산(10%→20%는 100% 증가, 비율 평균은 기하평균: SoK B3·B5). 같은 논문의 여러 행이 같은 양을 다르게 말하면 격리. 초록 대 본문 수치 대조(sciwrite-lint 항목). 기존 `claude_numbers_raw.tsv`, `codex_verify_metric_sources.py`를 여기로 모은다.
- 출력은 행마다 pass / quarantine / reject와 reason_code. 이 층의 결과에는 모델 판단이 섞이지 않는다.

### 3.4 재현율 측정층

재현율은 한 가지 추정으로 선언하지 않고 다섯 가지를 함께 보고한다.

1. **G 대비 재현율·정밀도.** 추출기 A, B, A∪B 각각. 필드 수준(주장 있음 / 조건 맞음 / 수치 맞음)으로 나눠 낸다. SciLitBench의 기울기(연도 0.97 → 방법 0.37)처럼 필드마다 다를 것을 전제한다.
2. **P 회수율.** 심어 둔 탐침 중 회수된 비율.
3. **T 회수.** 목표 집합 10개 전부 회수 여부.
4. **포획-재포획.** A만 잡은 것, B만 잡은 것, 둘 다 잡은 것으로 문단(또는 주장) 총수를 Chapman 추정. 독립 가정 위반 시 과소 추정임을 함께 적는다(Kastner 2009, Rücker 2011).
5. **Elusion 표본.** A·B 둘 다 쓰지 않은 문단에서 무작위 n개를 사람이 읽고 누락 주장을 센다. 정확 이항 상한으로 보고(Lewis 2021). 반복 실행 대칭차(같은 추출기 두 번)는 실행 불안정의 하한으로 따로 적는다(Figalová 2026).

게이트: 임계 미달이면 **잔여 문단만** 재추출한다. 논문 통째 재실행은 하지 않는다. 재추출 후 표본을 다시 뽑아 통과를 노리는 것은 금지(sequential bias). 기존 `$KVCPOOL/tools/quotes_coverage.py`는 옛 세트를 가리키므로 현재 두 벌과 `paragraphs`에 재조준한다.

### 3.5 교차 판정층

- A·B 행을 (paper_id, 스팬 겹침)으로 짝짓고 필드별 diff를 낸다.
- 필드별 Krippendorff α를 부트스트랩해 「α_min 미달 확률 q」를 보고한다(Hayes & Krippendorff 2007). 점추정 κ 하나로 통과를 선언하지 않는다.
- 불일치 행 = 사람 감사 대기열. 이 라우팅이 이중 추출의 주 용도다(Vivekanantha 2026: 둘 다 맞음 82%, 하나라도 맞음 95.1%).
- **일치는 검증이 아니다.** 둘이 함께 떨어뜨린 조건은 여기서 안 잡힌다. 일치 행도 6층과 8층의 표본에 든다.

### 3.6 충실성·귀속층

- **1차 전수 스윕.** (claim_text, quote+주변 문단) 쌍을 MiniCheck급 NLI로 SUPPORTS / REFUTES / NEI 판정하고 근거 스팬을 요구한다(TRUE·SummaC·MiniCheck; SciFact의 rationale 강제). 값싸므로 전수.
- **2차 보정 심판.** 플래그된 행과 무작위 행에만 LLM 심판을 쓴다. 조건: 사람 라벨 ≥100건으로 κ를 먼저 재고(Anthropic 2026 「closely calibrated」), 좌우 순서 교대(Wang 2023), 근거 선기술, Unknown 허용, 항목 단위(묶음 금지: Peng 2026). **단일 최고 심판**을 쓴다. 패널 다수결은 쓰지 않는다(Kohli 2026).
- **독립 검증 질문.** 「이 문장이 암묵 가정한 조건은?」을 레코드만 보이는 새 컨텍스트에서 답하게 하고 원 조건 필드와 대조한다(Chain-of-Verification).
- **귀속 3분류.** attributable / extrapolatory / contradictory(AttrScore). extrapolatory는 `kind`가 author_interpretation 이상이어야 통과.
- 모든 판정은 `checks.verifier_id`·`protocol_ver`와 함께 저장한다. 검증기가 다르면 비율을 비교하지 않는다(Goo 2026: 동일 출력에서 3%–18%).

### 3.7 조건 드리프트층(재정리마다)

- **링크 강제.** `synth_sentences.linked_row_ids`가 비면 문장을 쓸 수 없다. 빌더가 ID 존재만 assert하는 현재 상태에서 한 단계 올린다.
- **조건 포함 관계.** 종합 문장의 조건 집합이 링크된 레코드들의 조건 합집합보다 넓으면 플래그. 구체성 태그(더 구체적 / 더 일반적 / 인접, SciFact-Open)를 붙인다.
- **확신 표지 diff.** 원문 인용의 양태(may / suggests / in our setting)와 종합 문장의 양태(is / always)를 비교해 상승을 플래그(Belem 2026). 절대 표현 목록(반증·유일·범위 밖·항상)은 그대로 금지어로 둔다.
- **재실행 시점.** 요약·재배치·표 병합을 한 번 할 때마다. 중간 버전을 모두 남긴다(누적 효과를 추적하려면 버전이 필요하다).
- 조건이 안 풀리면 문장을 지우고 「판정 불가」 행으로 남긴다.

### 3.8 비교가능성층

- 비교표에 들어가는 행은 조건 5필드가 전부 채워져야 한다. 기준선 없는 값은 진입 금지(SoK D1).
- 행마다 GRADE식 확실성 기호(설계 등급 + indirectness 하향).
- 교차 논문 충돌은 「정의 다름 / 조건 다름 / 진짜 충돌」로만 분류하고, 설명 축은 실행 전에 등록한다. 사후에 찾은 설명은 「가설」 표기(Cochrane 10장). 41편 규모에서 정량 meta-regression은 하지 않는다.
- 이 층에 확립된 외부 방법은 없다(두 문서 공통 결론). 자체 스키마가 곧 방법이다.

### 3.9 사람 감사층

- **표본 설계를 먼저.** 층화: (a) Table 1에 쓰이는 고위험 행, (b) 4층 불일치 행, (c) 5·6층 플래그 행, (d) 무작위. 크기는 정확 이항 구간으로 정한다(300건 0오류 → 95% 상한 약 1%). 실행 전에 적고 재표집하지 않는다.
- **순서.** 담당자가 30행 이상을 원문과 직접 대조해 실패 분류를 만들고, 100행 풀에서 새 유형이 안 나올 때까지 확장한다(Husain & Shankar). 이 분류가 5·6층 검사기의 루브릭이 된다.
- **역할.** 사람은 처음부터 라벨하지 않고, 검사기·추출기가 낸 판정에 근거를 대며 이의를 제기하고 판정하는 감사자다(DeepFact: 60.8%→90.9%).
- **정답 섞기.** `gold` 행을 감사 대기열에 섞어 감사자 정확도를 재고, 4건 이상 본 뒤에만 계산하며, 정답에 이의를 제기할 수 있게 한다(Oleson 2011). 자동화 편향 경고(Vivekanantha 2026)가 여기 해당한다.

### 3.10 검증기의 검증

- **오류 주입.** 통과한 행을 복제해 오류를 심는다. 유형: 조건 삭제, 조건 넓힘, 수치 자리바꿈, 단위 변경, 양태 상승(may→is), 출처 논문 뒤바꿈, 인용 문자열 한 단어 교체. 각 검사기(L1, L2, L6, NLI, 심판, 드리프트)의 유형별 검출률과 오탐률을 `injections`에 기록한다(sciwrite-lint 방식, Nguyen 2026: 최고 단일 71.6%, 여섯 합집합 83.3%).
- **심판 보정.** 사람 라벨 대비 κ, 위치 편향(좌우 교대 시 뒤집힘 비율), 재검사 일치(test–retest). 일치율만으로 보고하지 않는다(Norman 2026).
- **재측정 시점.** 모델 판이 바뀌거나 프롬프트를 고칠 때마다. 검증기 성능은 생성기와 함께 움직인다(Wang 2606.26300).
- **게이트.** 검사기가 자기 표적 오류 유형에서 등록된 검출률을 넘지 못하면 그 층의 pass는 「미검증」으로 표기한다.

### 3.11 출시 게이트·출처 묶음

- §4의 등록 기준을 전부 충족했는지 기계가 확인한다. 하나라도 미달이면 산출물은 「초안」 상태로만 공개한다.
- **출처 묶음.** 입력 해시, `runs`, 모든 `checks`, `audits`, `synth_sentences` 전 버전, 등록 기준 파일과 그 해시를 함께 봉인한다(Claude Science의 코드·환경·메시지 이력, NeurIPS 2026의 버전 이력, Springer Nature·ICMJE의 도구·프롬프트 공개).
- **결과 문장 규칙.** 모든 종합 문장에 조건을 붙이고, 관측과 이득을 구분하고, 검증기 이름을 밝힌다.
- **이해 게이트.** 담당자가 표의 임의 행 10개를 원문 없이 설명하고 임의 범주 3개의 소속 근거를 말할 수 있는가. 못 하면 검증이 아니라 전달이다(Tao, Gruhn의 「자기 말로 다시 쓰기」).
- **가치는 따로.** 충실한 표가 곧 기여는 아니다(Buzzard). 이 시스템은 맞음까지만 보증한다.

## 4. 예산 배분과 임계값

**예산.** 누락이 오류의 다수이므로 3층(재현율)과 6층(조건 드리프트)에 사람 시간을 먼저 배정한다. L1 존재 검사는 값싸고 거의 풀린 문제이니 전수로 돌리되 시간을 쓰지 않는다(2026 검출기 88–97%). 두 번째 모델 실행은 싸지만 독립 신호가 적으므로 「라우팅용」으로만 값을 매긴다.

**임계값 예시.** 아래는 실행 전에 프로젝트 값으로 바꿔 등록해야 하는 자리이고, 문헌에서 온 것만 출처를 달았다.

| 항목 | 예시 임계 | 비고 |
|---|---|---|
| L1 존재·포함 | 100% pass, waiver는 사유 코드 필수 | 실패는 기각 |
| L2 스키마 완결 | 비교표 진입 행 100% | 미완은 격리 |
| T 회수 | 10/10 | 95% 신뢰 recall ≥ 0.7(Cormack & Grossman) |
| G 대비 주장 재현율(A∪B) | ≥ 0.9, 필드별 별도 보고 | 프로젝트 값 |
| Elusion 표본 | n은 원하는 상한에서 역산, 재표집 금지 | 정확 이항 |
| α(수치·조건 필드) | q(α < 0.67) ≤ 0.05 | 부트스트랩(Hayes & Krippendorff) |
| 심판 보정 | 사람 라벨 ≥ 100건, κ ≥ 0.7, 순서 뒤집힘 ≤ 5% | 프로젝트 값 |
| 사람 표본 | 300행 0오류 → 상한 ≈ 1% | 정확 이항, 층화 |
| 검사기 주입 검출률 | 표적 유형 ≥ 0.9, 오탐 ≤ 0.1 | 프로젝트 값 |
| 종합 문장 링크 | 100% | 링크 없는 문장 없음 |

## 5. 이 프로젝트에서의 구축 순서

**1차(원장과 결정론적 층).** `claims`·`paragraphs`·`checks` 원장 만들기. 기존 Claude 804·Codex 1,164 레코드를 스키마로 옮기기(부족한 조건 필드는 「없음」으로 채우고 격리). `quotes_verbatim_check.py`를 L1으로, `codex_verify_metric_sources.py`·`claude_numbers_raw.tsv`를 L6로 편입. waiver 구조화.
**2차(재현율).** G 3편 손 추출, T 10개 선정, P 심기. `quotes_coverage.py`를 `paragraphs`에 재조준. A/B 포획-재포획과 elusion 표본 스크립트.
**3차(교차 판정·감사 대기열).** 행 짝짓기 + 필드 diff + α 부트스트랩. 불일치 대기열 UI는 스프레드시트로 충분하다. 30행 직접 대조 → 실패 분류.
**4차(충실성·드리프트).** NLI 전수 스윕, 보정 심판, 독립 검증 질문. `synth_sentences` 링크 강제와 조건 포함·양태 diff. 빌더의 assert를 이 검사로 대체.
**5차(검증기 검증·게이트).** 오류 주입 세트, 검사기 성능표, 등록 기준 파일과 출시 게이트, 출처 묶음.

각 차수는 앞 차수의 원장을 그대로 쓰므로 독립 세션으로 나눠 진행할 수 있다.

## 7. 미해결

- 7층(정의 비교가능성)에는 확립된 외부 방법이 없다. §3.8의 스키마가 자체 방법이며, 이 부분은 논문에서 기여로 주장할 수 있다.
- 조건 드리프트 검사의 자동화 성능은 2026년 문헌에도 수치가 없다. 오류 주입(§3.10)으로 자체 측정하는 것이 유일한 길이다.
- 포획-재포획의 독립 가정은 두 추출기가 같은 문단을 같은 이유로 놓칠 때 깨진다. 추정치는 항상 하한으로 읽고 elusion 표본과 함께 보고한다.
- 사람 감사자의 영역 지식 부족은 시스템이 보정하지 못한다(Mollick, Lahlou의 역설). 감사자 배정 자체가 설계 결정이다.
