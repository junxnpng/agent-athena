## A. 심어 둔 정답으로 재기 (known-answer)

**A1. 오류 주입 = 원장의 변이 테스트.** 통과한 레코드를 복제해 변이 연산자를 적용한다. 인용 한 단어 치환·삭제, 수치 자리바꿈, 단위 변경, 조건 삭제·확대, 양태 상승(may→is), 출처 논문 뒤바꿈, locator 이동, 주장–인용 짝 바꾸기(다른 레코드의 주장을 붙임), 두 레코드 병합. 연산자별 「죽인 변이 비율」이 검증기의 점수다. 의미가 안 바뀌는 변이(동의어 치환)는 잡지 말아야 하므로 오탐 측정에 쓴다(등가 변이 문제의 원장판).
【네 판정 모두, 유형별】【낮음: 연산자는 코드 수십 줄】【변이 테스트: Lipton 1971 제안, DeMillo·Lipton·Sayward 첫 발표, Budd 1980 첫 도구. "The value of a test suite is measured by the percentage of mutants that it kills." sciwrite-lint 2026: 30편 오류 주입 + LLM 판정 오탐 분석. Nguyen 2026: 주입 오류 검출 71.6%(단일)/83.3%(6모델 합집합). HalluPeer 2026: 주입 환각을 detection·classification·localization 세 과제로 채점】

**A2. 오류 심기로 잔여 오류 추정(bebugging).** 실제 레코드 세트에 실제 오류와 닮은 오류를 몰래 심고 검증을 돌린다. 심은 것 중 잡힌 비율 p로 진짜 오류의 잔여량을 추정한다(잡힌 진짜 오류 × (1−p)/p). 약점: 심은 오류가 진짜 오류를 닮아야 한다. 그래서 심는 유형은 이 프로젝트에서 사람이 이미 찾은 오류 분류에서 뽑는다.
【검증 후 남은 오류의 양】【낮음】【Weinberg 1970, Mills의 fault seeding. "The percentage of the known bugs not found gives an indication of the real bugs that remain."】

**A3. 탐침·목표 집합.** 사람이 미리 고른 「반드시 잡혀야 할」 스팬 10개와 심어 둔 정답 레코드. 10/10 회수면 95% 신뢰로 recall ≥ 0.7. 재현율 추정치가 맞는지의 직접 표본.
【재현율 판정의 타당성】【사람 시간 소량】【Cormack & Grossman target method, Oleson 2011 programmatic gold】

**A4. 합성 코퍼스 픽스처.** 주장·수치·조건을 전부 알고 있는 짧은 가짜 논문 2–3편과, 거기서 뽑은 「정답 추출」과 「오류를 알고 심은 추출」을 만든다. 파이프라인 끝까지 돌려 기대 보고서와 diff. CI에서 매번 돈다.
【배관 전체의 회귀】【중간: 한 번 만들면 재사용】【소프트웨어의 golden test 관행】

## B. 사람 기준으로 재기 (human reference)

**B1. 층화 표본과의 일치.** 사람이 판정한 100–300행(고위험·불일치·플래그·무작위로 층화)과 검증기 판정의 κ 또는 α를 부트스트랩해 「α_min 미달 확률」로 보고. 일치율(exact match)로는 안 된다. 사람끼리의 일치도도 같이 재서 천장을 안다.
【합치 3분류·조건 보존의 타당성】【사람 시간 중간】【Norman 2026: 일치율은 κ보다 33–41pp 과대, 위치 편향·재검사 함께. Hayes & Krippendorff 2007. Kim 2026: 사람 리뷰어끼리 겹침 3%. Anthropic 2026 「closely calibrated with human experts」】

**B2. 감사-후-채점(Audit-then-Score).** 검증기와 사람이 불일치할 때 검증기(또는 사람)가 근거를 내고 감사자가 판정해 정답을 고친다. 정답 세트가 진화하고, 사람은 라벨러가 아니라 감사자가 된다.
【정답 세트의 품질, 사람 정확도】【사람 시간 중간】【DeepFact 2026: 전문가 60.8% → 4라운드 후 90.9%】

**B3. 회귀 시험: 이미 사람이 찾은 오류.** 9-15 리뷰, claude_50 §1-a 21건, merge-log N6 5쌍, waiver 48건(정당한 예외와 진짜 오류 구분)을 테스트 케이스로 굳힌다. 검증기가 이것들을 독립적으로 다시 찾아야 한다.
【실제 분포의 오류에 대한 검출】【낮음: 이미 있음】【소프트웨어 회귀 테스트 관행】

**B4. 그림자 모드.** 게이트로 쓰기 전에 N회는 기존 수작업 리뷰와 나란히 돌려 결정을 비교만 한다. 사람이 잡고 검증기가 놓친 것, 검증기가 잡고 사람이 놓친 것을 모두 기록한 뒤 승격.
【실전 분포에서의 누락·오탐】【사람 시간은 기존 리뷰와 겹침】【ML 배포 관행. Husain & Saha 2026: 자동 평가가 사람 오류의 87% 회수, 「맞아 보이는」 실패는 항상 놓침】

## C. 정답 없이 성질로 재기 (oracle-free)

**C1. 메타모픽 관계.** 기대 출력을 몰라도 「입력을 이렇게 바꾸면 출력은 이래야 한다」는 관계로 검사한다. 예: (a) 주장을 뜻이 같게 바꿔 써도 판정 불변, (b) 주장의 수치를 바꾸면 보존 판정이 뒤집혀야 함, (c) 레코드 순서·좌우를 바꿔도 판정 불변(위치 편향), (d) 관련 없는 문단을 컨텍스트에 더해도 존재 판정 불변, (e) (주장, 인용)이 SUPPORTS면 (부정 주장, 인용)은 REFUTES 또는 NEI, (f) 레코드 부분집합만 돌려도 각 행의 판정은 전체 실행과 같음(독립성).
【심판의 일관성·편향, 검사기 논리 오류】【낮음: 관계 하나가 테스트 하나】【T.Y. Chen 1998. "The test oracle problem is the difficulty of determining the expected outcomes..." 예: 가격 필터 후 결과는 원 결과의 부분집합이어야 함】

**C2. 재검사 일치(test–retest).** 같은 입력을 두 번 넣어 판정 뒤집힘 비율을 단계(tier)별로 잰다. 비결정적 단계의 잡음 하한이다.
【심판 잡음】【토큰 2배, 사람 0】【Figalová 2026: 동일 실행 둘이 8.3% 불일치. Oami 2026: 세션 간 일관성 44.8–91.3%】

**C3. 차등 테스트.** 같은 검사를 독립 구현 둘(NLI 모델 둘, 프롬프트 둘, PDF 파서 둘)로 돌려 불일치를 「어려운 사례」로 모은다. 불일치 자체가 버그 후보다.
【구현 의존적 오류, 어려운 사례 발굴】【낮음~중간】【소프트웨어 차등 테스트. Goo 2026: 검증기 간 음성 일치 0.27–0.30이므로 불일치는 많을 것】

**C4. CheckList식 행동 테스트 행렬.** 능력(부정, 수치·단위, 한정어·양태, 범위 조건, 대용어, 문단 넘는 참조) × 시험 유형(최소 기능: 쉬운 사례는 반드시 통과 / 불변: 바꿔도 같아야 / 방향: 바꾸면 정해진 방향으로 변해야)의 표를 채운다. A1과 C1을 조직하는 틀이다.
【능력별 빈 구멍】【중간】【Ribeiro et al. 2020: 상용 모델에서 새 버그 발견, CheckList 사용 시 테스트 2배·버그 3배】

## D. 적대적으로 깨기 (adversarial)

**D1. Build it / Break it / Fix it.** 다른 모델(또는 사람)에게 「검증기를 통과하지만 틀린 레코드」를 만들게 한다. 인용은 진짜인데 주장이 미묘하게 어긋남, 수치는 맞는데 단위가 바뀜, 조건이 조용히 넓어짐 등. 통과율이 검증기의 취약점 지도다. 고친 뒤 다시 깬다.
【검증기의 사각】【중간: 공격자 모델 비용】【FEVER 2.0(Thorne 2019): 빌더 8, 공격자 5, "under adversarial evaluation, all systems exhibited losses in FEVER score"】

**D2. 게이밍 시험.** 발췌기에 검증기의 규칙을 그대로 보여 주고 최소 노력으로 통과하게 해 본다(자명한 문장만 인용, 조건 필드에 상투어). 통과하면 그 검사는 게이밍 가능하므로 대역 밖으로 옮긴다.
【검사의 우회 가능성】【낮음】【Tao 2026 Dwarkesh: RL은 뒷문을 찾는다. Karpathy autoresearch: 채점기는 수정 불가 파일】

**D3. 추출 노이즈 강건성.** 하이픈 분절, 합자, 열 순서, 각주 끼어들기 같은 PDF 추출 잡음에 존재 검사가 얼마나 오탐(MISS)을 내는지. 저장소의 raw/layout 텍스트 쌍과 waiver 48건이 바로 그 데이터다.
【존재 검사 오탐】【낮음】【이 프로젝트 자체: waiver 사유 코드】

## E. 단계식(cascade) 특유의 시험

**E1. 승격 누출률.** 소형 단계가 「통과」시킨 항목에서 표본을 뽑아 고가 단계(또는 사람)가 다시 판정한다. 통과 항목 중 틀린 비율을 정확 이항 상한으로 보고. 단계식의 elusion이다.
【싼 단계가 흘려보낸 오류】【고가 모델 토큰 소량】【Lewis 2021 elusion; Cormack & Grossman】

**E2. 보정 곡선과 conformal 보증.** 소형 단계의 확신값을 사람 정답과 대조한 reliability diagram으로 승격 임계를 정하고, split-conformal로 「놓친 미지지 인용 수」에 유한표본 상한을 건다.
【임계 선택의 근거, 통계적 보증】【중간】【Goo 2026: conformal guard, 검증기 recall 0.94(지지 클래스)】

**E3. 컨텍스트 절단 충분성.** 고가 단계에 문단만 / 문단±1 / 절 전체를 줄 때 판정이 바뀌는 비율. 바뀌지 않는 최소 컨텍스트가 토큰 절약의 상한이다.
【컨텍스트 절단으로 생기는 오판】【토큰 중간, 한 번】【Konet 2024: 발췌 입력이 더 정확. Tan & D'Souza 2026: 긴 컨텍스트가 튜플 결합을 악화】
