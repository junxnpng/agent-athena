# Ralph — 검증 근거를 갖출 때까지 구현·리뷰·수정

먼저 [공통 실행 계약](../shared/PORTABILITY.md)을 읽는다. 이 스킬은 현재 세션의 작업 방식이다. 자동 재시작·무제한 실행·별도 상태 저장을 제공하지 않는다.

## 시작

사용자 요청과 기존 사양에서 완료 조건을 확인한다. 각 조건을 관찰 가능한 결과와 연결한다. “구현 완료” 같은 순환적인 기준은 구체적인 입력·동작·출력으로 바꾼다. 이미 합의한 범위를 다시 승인받지 않는다. 필요한 사용자 결정이 없다면 작업을 시작한다.

러너 모드에서는 할당된 현재 작업만 처리한다. 다른 큐 항목 선택·다음 밤 시작·시도 상태 변경은 러너에 맡긴다. 대화형에서는 사용자가 요청한 전체 범위를 순차 수행한다. 기존 실패 흔적을 읽고 검증 없이 같은 접근을 반복하지 않는다.

## 구현과 검증

- 기존 구조를 확인하고 완료 조건을 만족시키는 작은 변경을 만든다. 쓰기 작업은 순차 수행한다.
- 해당 조건을 실제로 판별하는 검사·테스트·시연을 실행하고 출력과 종료 결과를 읽는다. 실패하면 원인에 맞게 고친다. 통과를 위해 요구사항이나 검사를 약화시키지 않는다.
- 조건이 충족되면 변경 파일뿐 아니라 관련 호출부·경계 조건·기존 사용자 동작을 리뷰한다. 현재 정책이 허용하는 독립 읽기 전용 리뷰어가 있으면 사양·변경·검증 근거를 제공한다. 없으면 직접 별도 리뷰하고 그 한계를 밝힌다.
- 정확성 외에 불필요한 추상화·중복·새 의존성이 있는지 확인한다. 리뷰에서 찾은 실제 문제만 수정하고, 수정한 동작의 검증을 다시 실행한다. 리뷰 통과 후 무관한 정리 작업을 추가하지 않는다.

## 끝내기와 한계

모든 요청 조건에 검증 근거가 있고 남은 리뷰 문제가 없을 때 완료를 보고한다. 변경·검증 결과·미실행 검사·실제 한계를 구분한다. 검증 불가를 성공으로 처리하지 않는다.

사용자가 중단하면 즉시 멈춘다. 자격증명·필수 결정·외부 장애로 더 진행할 수 없거나 같은 접근에서 새 정보가 나오지 않으면 실패 근거와 필요한 다음 입력을 보고한다. 호스트의 시간·예산·시도 제한을 따르며, 모델이 자체 카운터나 PRD의 성공 플래그를 기록하지 않는다. 러너 모드에서는 현재 결과를 반환해 기존 프로그램이 판정하도록 한다.
