# Writing for agents

먼저 [공통 실행 계약](../shared/PORTABILITY.md)을 읽는다. 스킬의 호출 정책·파일 구성을 바꿀 때는 [스킬 구성](SKILL-MECHANICS.md)도 읽는다.

## 언제 읽을지부터 명확하게

문서를 가리키는 description이나 링크 문장은 무엇을 제공하는지와 어느 상황에서 읽어야 하는지를 함께 말한다. 모든 세션에 노출되는 설명은 실제 분기만 담고 동의어 목록으로 늘리지 않는다. 본문이 정확해도 호출 조건이 흐리면 필요한 순간에 읽히지 않는다.

## 필요한 순서에 배치

공통 결정과 필수 절차는 본문에, 특정 경우에만 필요한 예시·세부 규약은 조건이 적힌 링크 뒤에 둔다. 분리한 파일은 실제 읽기 경로로 연결한다. 서로 다른 내용이 섞이면 분리하되 짧은 문서에 불필요한 라우터를 만들지 않는다.

각 단계에는 관찰 가능한 종료 조건을 둔다. “충분히 이해”, “잘 검증” 대신 무엇을 대조하고 어떤 미결정이 없어야 하는지 적는다. 완료 기준이 흐려 다음 단계로 서두르면 먼저 기준을 고친다. 파일 분리만으로 같은 세션의 문맥이 사라진다고 가정하지 않는다.

## 하나의 규칙은 한 곳에

의미가 같은 규칙은 정본 한 곳에 두고 참조한다. 규칙의 이유·예외·적용 조건은 가까이 둔다. `package.json`, CLI 도움말, 실제 설정에서 쉽게 얻을 값은 문서에 복제하지 않는다. 설명 없이는 알 수 없는 관례와 선택의 이유를 남긴다.

이미 통용되는 용어를 우선하고, 새로운 용어는 실제로 여러 판단을 단순화할 때만 정의한다. 금지 목록보다 원하는 행동을 먼저 적되 권한·보안·데이터 손실 경계는 명시적으로 보존한다.

## 리뷰

실제 요청 예시로 읽을 문서와 다음 행동을 따라가 본다. 필요한 파일이 모두 포함되는지, 도구가 없는 환경에서도 끝낼 수 있는지, 너무 넓은 트리거가 다른 작업을 가로채지 않는지 확인한다. 정책을 prose에 썼다는 이유로 프로그램이 강제한다고 주장하지 않는다.

모델이 이미 잘하는 일반 조언, 같은 의미의 반복, 실제 행동을 바꾸지 않는 문장은 제거한다. 사용자 의도·실패 기록·권한 경계를 지운 요약은 간결화가 아니다.
