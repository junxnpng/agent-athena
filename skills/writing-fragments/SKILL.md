# Writing fragments — 글감 수집

먼저 [공통 실행 계약](../shared/PORTABILITY.md)을 읽는다. 아직 글의 구조를 정하지 않고 쓸 만한 재료를 넓힌다. 최종 글이 요청된 상황을 인터뷰로 바꾸지 않는다.

사용자가 지정한 파일을 사용한다. 저장 경로가 없으면 적절한 기존 관례를 찾고, 선택이 필요하면 한 번 묻는다. 최초 입력부터 장면·경험·주장·비유·문장·아직 덜 익은 생각을 포착한다. 사용자가 실제로 한 말과 에이전트가 제안한 문장을 혼동하지 않는다. 사실이나 직접 인용의 출처가 불확실하면 그 점을 글감 안에 표시한다.

질문은 구체적인 경험과 관찰을 끌어내는 데 쓴다. 작가가 이해할 수 있으면 충분하며, 아직 독자용 정의나 논증을 완성할 필요는 없다. 반복되는 생각을 잘 표현하는 단어가 있으면 제안하되 억지로 이름을 만들지 않는다.

## 파일과 편집

처음에는 작업 제목 H1 하나를 두고, 글감 사이를 `---`로 나눈다. 불필요한 메타데이터·목차·태그·구조를 붙이지 않는다. 글감은 문장, 단락, 인용, 코드, 관찰 목록 등 자연스러운 형태를 유지한다.

매번 파일을 다시 읽고 기존 내용과 사용자 편집을 보존하며 새 글감만 추가한다. 조각마다 저장 승인을 반복해서 묻지 않는다. 특정 조각의 삭제·수정·병합 요청은 해당 부분에만 적용한다. 수집을 멈추라는 요청이면 멈춘다. 구조화는 사용자가 원할 때 [writing-shape](../writing-shape/SKILL.md) 또는 [writing-beats](../writing-beats/SKILL.md)로 이어간다.
