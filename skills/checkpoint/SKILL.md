# checkpoint — 메모리 정리 + 새 세션 프롬프트

목적: `/compact` 는 모델이 쓴 요약이 컨텍스트에 남아 관성(틀린 가정·낡은 세부)을 끌고 간다. 체크포인트는 **파일에 일부러 쓴 것만** 다음 세션이 읽게 해 관성을 끊는다.
이 스킬은 코드를 고치지 않고, 커밋하지 않고, 새 작업을 시작하지 않는다. 출력은 메모리 파일 갱신 + 프롬프트 블록 하나다.

## 0. 먼저 판단
- 작업 방향이 그대로이고 컨텍스트만 찼다 → 이 스킬 대신 `/compact <보존할 것>` 을 권하고 끝낸다.
- 방향이 바뀌었다 · 틀린 시도가 많았다 · 다른 세션/사람이 이어받는다 → 계속.

## 1. 사실 수집 (추측 금지 — 대화와 파일에서 확인한 것만, 불확실은 `(미확인)`)
대화를 처음부터 훑어 아래 여섯 칸을 채운다. 각 항목은 경로·커밋 SHA·id·숫자처럼 **다음 세션이 검증할 수 있는 형태**로.
1. 완료한 것 — 무엇을, 어디에(repo·경로·커밋), 검증 결과(테스트 수·check 결과)
2. 진행 중인 것 — 어느 단계까지 됐고 무엇이 남았나, 돌고 있는 프로세스(pid·모니터)가 있나
3. 결정과 이유 — 사용자가 내린 결정·지시(원문 표현 유지), 내가 내린 판단과 근거
4. 대기 — 사용자의 답이 필요한 것(승인·선택), 외부 행동(토큰·등록·입력)
5. 틀렸던 것 — 이 세션에서 정정된 가정·실패·놓친 것 (다음 세션이 같은 실수를 안 하게)
6. 다음 단계 — 순서대로, 첫 단계는 즉시 실행 가능한 명령 수준으로

그다음 파일로 대조한다: 대화에 나온 repo 마다 `git -C <repo> status -sb` · `git -C <repo> log --oneline -3`, 하네스 repo 가 있으면 `scripts/morning-digest --dry-run`. 대화와 다르면 **파일이 맞다** — 파일 기준으로 고친다.

## 2. 메모리 갱신
- 메모리 디렉토리 = 시스템 프롬프트가 알려준 곳(`MEMORY.md` 가 있는 디렉토리). 없으면(다른 런타임) 현재 repo 의 `HANDOFF.md` 하나에 쓰고 커밋하지 않는다.
- **있는 파일을 먼저 갱신**한다(주제가 겹치는 파일을 찾아 현재 상태·다음 단계·대기 결정을 바꿔 쓴다). 새 파일은 새 주제일 때만. frontmatter(`name`·`description`·`metadata.type`)와 본문 형식은 기존 파일과 같게, 날짜는 절대 날짜로.
- 틀렸던 가정은 지우지 말고 "정정: …(날짜)" 로 남긴다. repo 가 이미 기록하는 것(코드 구조·git 이력·CLAUDE.md)은 쓰지 않는다.
- `MEMORY.md` 인덱스의 해당 줄(들)을 한 줄 요약으로 갱신한다 — 내용은 인덱스에 쓰지 않는다.
- 하네스 어휘 충돌·가정 변경이 있었는데 `CONTEXT.md`·`ASSUMPTIONS.md` 에 안 남았다면 그건 체크포인트가 아니라 남은 작업이다 — 6번 목록의 첫머리에 넣는다.

## 3. 새 세션 프롬프트 출력
프롬프트를 **파일에 쓰고 클립보드에 넣는다** — 터미널에서는 코드 블록의 경계가 보이지 않아 어디부터 복사할지 애매하다(2026-08-30 실측).
1. `~/.claude/harness-new-session-prompt.md` 에 저장한다(덮어쓴다 — 최신 하나만 의미 있다).
2. 클립보드: macOS `pbcopy < 파일`, Linux `xclip -selection clipboard < 파일` 또는 `wl-copy < 파일`(있는 것으로, 없으면 건너뛴다).
3. 채팅에는 블록을 다시 붙이지 말고, 새 세션의 **첫 메시지로 칠 한 줄**을 준다(클립보드는 터미널의 선택-복사에 덮이므로 보조 수단이다, 2026-08-30 실측):
   `~/.claude/harness-new-session-prompt.md 를 읽고 그 지시대로 시작해` — 이 한 줄이면 새 세션이 파일을 읽어 그대로 따른다. 클립보드에도 넣어두되 "덮였으면 위 한 줄" 이라고 덧붙인다.
형식(40줄 이내, 한글):

```
<프로젝트 한 줄> 작업을 이어간다. 먼저 읽을 것(이 순서로): CLAUDE.md → 메모리 <파일명 2~4개> → <꼭 읽어야 할 파일·경로>.

현재 상태 (<절대 날짜 시각>):
- <repo/모듈>: <커밋 SHA·테스트 수·돌고 있는 것> …(3~6줄)
- 틀렸던 것: <정정된 가정 한 줄씩>

규칙: <이 프로젝트의 운영 규칙 — 사용자가 세션마다 반복해 말하는 것. 예: git은 네가 한다, 승인 단어, 금지 사항>

지금 할 일 (순서):
1. <즉시 실행 가능한 첫 단계 — 명령 수준>
2. …
대기 중인 결정: <사용자 답이 필요한 것>. 먼저 짧게 상태 보고만 하고 코드는 건드리지 마라.
```

## 하지 말 것
- 대화에 없는 것을 그럴듯하게 채우기 · 진행 중인 프로세스를 끝내거나 커밋하기 · 메모리 디렉토리 밖(도메인 repo)에 요약 파일을 흩뿌리기 · 프롬프트에 비밀(토큰·경로 속 자격증명) 넣기.
